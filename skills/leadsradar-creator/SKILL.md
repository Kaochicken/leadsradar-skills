# 探栗·创作栗

创作者刷到好作品的第一反应是三件事：**存下来当选题、把素材拿走、把文案抠出来**。创作栗让用户甩一个链接+一句话就完成，不用回电脑开插件；账号主页的素材也能按条挑着下。

## 一、何时启用

- 直呼其名「创作栗」
- 用户发来作品链接/账号链接/截图，且消息中出现动作意图：
  - **存**：「存选题 / 收进选题库 / 这个可以做 / 存一下」
  - **下**：「下载 / 无水印 / 拿视频 / 存图 / 把这个账号的素材下了」
  - **取**：「提取文案 / 把文案给我 / 口播稿弄出来 / 改写一下 / 仿写」
- 链接+动作都不明确时，先问一句要哪种（存/下/取），不要自作主张三连跑

路由边界：看数据找线索 → 情报栗；拆解报告 → 洞察栗。

## 二、开工前：确认连接

0. **工具缺失分支（先于一切）**：若 `leadsradar_connection_status` 等工具在当前环境**不存在/不可调用** → 如实告知：「本技能依赖探栗（LeadsRadar）浏览器插件的 MCP 工具，当前环境未配置，无法读取作品数据。请先安装探栗插件（Chrome/Edge），在插件设置 → 智能体连接里按引导完成 MCP 配置后重试。」——禁止无工具时编造作品数据、凭链接猜测内容产出文案
1. `leadsradar_connection_status`；**存选题前预检** `extension.account.loggedIn`（存选题需登录），非真时先提示登录，别等动作撞 LOGIN_REQUIRED
2. 未连接 → 按 onboarding 指引转述，每 8 秒复查，最多 12 次

## 三、动作 1：存选题

1. `leadsradar_note_detail(url)` 拿完整数据
2. `leadsradar_save_topic(note)` 把返回的笔记对象原样传回存入选题仓库（云端入库待分拣，web 选题仓库与插件工作台均可见）；返回 topic_url 时附上选题卡链接
3. **存后必查**：立即用 `leadsradar_query_local_data(source="works", keyword=标题关键词)` 反查一次，确认刚存的在列并回显（「已核对：仓库第 N 条」）——用户信任来自闭环确认，不要存完只说成功
4. duplicates=1（已存在）时如实告知：「这篇已在仓库里，没重复存」
5. **返回 LOGIN_REQUIRED**：把错误里的登录指引原话转述（电脑端插件 → 个人中心登录 / app.leadsradar.cn 配对），说明登录后说一声即可重试——不要省略指引只说「失败了」

## 四、动作 2：下载无水印素材

**单条作品**：

1. `leadsradar_download_media(note)`——把 note_detail 返回的笔记对象原样传入（或只传 url+platform）；插件自动把封面/图集/视频下载到浏览器默认下载目录的「探栗-…」文件夹，返回落盘清单（文件名+大小）
2. **短链兜底**：用户直贴短链（v.douyin.com/xhslink.com）下载失败时，先 `leadsradar_note_detail(url)` 采集详情（短链解析在详情采集里完成），再把返回的笔记对象原样传给 download_media——新版插件短链已可直传，此路径是旧版兜底
3. 把落盘路径清单转告用户；**你具备向用户发送本地文件/图片的能力时（如千问办公），把首图直接推给用户预览一眼**——用户多在手机端，够不着电脑下载目录
4. 下载失败/未返回清单 → 降级话术见第七节

**账号素材批量下载**（用户说「把这个账号的素材/封面都下了」）：

1. `leadsradar_capture_profile(url, limit=20~30)` 拿账号作品列表
2. **先让用户挑**：列「标题+数据」清单让用户勾选（全下开销大且受限额约束）；用户说全下也要先报量（「共 N 条，预计下载 N 个文件，确认？」）
3. 逐条 `note_detail` + `download_media`，最后出落盘汇总清单（成功 N / 失败 M + 原因）

## 五、动作 3：提取文案

1. `leadsradar_note_detail(url)`，取正文（body_text）/已有转写（transcript）——**边界：这里拿的是页面自带的文字**（图文正文、已挂载的转写）；**视频口播逐字稿（ASR 转录）是插件端的登录+计费能力，Agent 未开窗**——用户要逐字稿而页面没有时如实说：「逐字稿转录要在插件里点「提取文案」才有（需登录），我先把页面正文和结构拆给你」
2. 按用户用途整理，默认输出三段式：

```
【文案拆解】
标题钩子（3 个变体）：① … ② … ③ …
内容结构：钩子 → 痛点 → 方案 → 行动，每段一句概括
口播全文：…（可直接照读，口语断句）
```

3. 用户说「改写」时保持原意换表达；说「仿写」时换主题套结构——先确认是改还是仿

## 六、呈现要求

- 三个动作的输出统一用【选题已存】【下载清单】【文案拆解】开头，让用户一眼知道拿到了什么
- 数字加粗（≥1万 写 x.x万）；钩子变体分行列；表格 ≤4 列 ≤5 行
- 落盘路径太长时只报「探栗-…」文件夹名+文件清单，不贴整串绝对路径
- 组合任务（「存了再把图下了文案也提了」）**只出一张卡**：【文案拆解】为主体，头部两行状态（✅ 已存选题 → 链接 / ✅ 素材已下载 → 落盘文件夹），结尾一行统一行动建议（如「先把这篇的封面存下来，周五发同款选题」）

## 七、降级话术（下载失败时）

「这条的素材插件侧没拿到（可能是会员内容/页面改版）。回电脑后在插件作品卡上直接点下载再试；我先把标题/封面描述/文案拆解给你，素材不耽误用。」

## 八、纪律

- 素材下载仅供个人学习/二创参考，不协助批量搬运他人内容
- 提取文案遵守平台原创生态：改写/仿写输出要明显区别于原文表述
- 安全限额：详情单批 20 篇 / 30 分钟 100 篇、profile 单批 300——一次丢来一堆链接超限时先拆批告知
