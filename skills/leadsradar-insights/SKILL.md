# 探栗·数据问答

用户不想打开插件翻页面，只想像问助理一样问一句：**「昨天的日报呢」「我仓库里存了多少选题」「上个月那份账号研究报告说了啥」**。本技能负责把问题路由到插件本地数据并给出直接答案。

当前状态：选题/作品/账号/评论/**报告**类问题已可直查（报告=插件本地缓存的四类 AI 研究报告）；监控/档案/日报类待对应查询通道上线（见第四节）。

## 一、何时启用

用户问题指向「我的数据 / 已有的东西」，而非「去平台采新的」：

- 报告类：「之前的拆解报告 / 账号研究报告 / 赛道报告给我看看」
- 选题类：「选题仓库有什么 / 日历这周排了啥」
- 监控类：「我监控了哪些号 / 监控规则是什么」（只读，不代改）
- 档案类：「我的成交档案 / 风格档案」
- 日报类：「今天/昨天的获客日报」

## 二、开工前：确认连接

先 `leadsradar_connection_status`；本技能查的是插件本地数据，插件必须在线。

## 三、问答流程

1. **问题分流**：判断问的是哪类数据（选题/作品/账号/评论/报告 → 可直查；监控/档案/日报 → 见第四节降级）
2. 选题/作品/账号/评论类调 `leadsradar_query_local_data`：选题仓库与已存选题用 `source="works"`，全部采集过的作品用 `source="notes"`，账号用 `source="accounts"`，某篇的评论用 `source="comments"`（须带 `note_url`）；支持 `keyword` 模糊搜标题/作者、`platform` 过滤、`limit`（≤200）
3. **报告类调 `source="reports"`**（⭐v1.2 开窗）：返回本地缓存的四类 AI 研究报告——`type=note` 作品拆解 / `account` 账号研究 / `track` 赛道研究 / `account_review` 账号复盘，每条含标题、一句话建议（`quick_advice`）、**web 直达链接（`report_url`）**。回答口径：先念标题+quick_advice 摘要，再把 `report_url` 给用户点开看完整报告（报告全文与完整 UI 在 web 端渲染，AI 不做全文搬运）；支持 `keyword` 搜标题
4. **先给结论再给数据**：一句话回答问题本体，再附支撑明细；数字加粗，长列表折叠为「展开看 N 条」；返回 `truncated=true` 时注明「共 N 条，先列前 M 条」
5. 查不到时如实说「没查到」，并给出可能原因（还没采集过/关键词不对/报告尚未生成过），不要编

## 四、降级话术（监控/档案/日报类问题）

按问题类型指路，一次说清位置，不要让用户在插件里瞎找：

- 监控/档案/日报类：指路 + 提议记忆问题待点亮后回答。

**降级时的一致口径**：「这几类数据的直查通道马上开通，开通后这类问题你直接问我就行，不用再翻插件。选题/作品/账号/评论/报告现在就能查。」

## 五、边界与纪律

- **只读不写**：用户要求「帮我把监控改成 XX / 删掉这个选题」——明确告知当前 AI 只能查不能改，改动请用户在插件内操作（避免误操作风险）
- **报告时效**：本地缓存的是生成时刻的报告快照（各类型只留最近 10 份），回答时注明「截至报告生成时」；`report_url` 指向云端真源，以 web 端打开为准
- 涉及成交档案等敏感数据：只在当前对话内引用，不主动复述到无关话题
- 数据答案须注明时间点（「截至上次采集」），避免用户拿旧数据当实时
