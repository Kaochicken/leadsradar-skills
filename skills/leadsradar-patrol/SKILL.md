# 探栗·对标巡逻

用户经营账号需要每天知道两件事：**对标们干了什么新动作**、**我自己的号表现怎么样**。本技能把「打开 N 个主页逐个翻」变成一句话巡逻，输出一份可直接决策的巡逻摘要。

当前状态：现扫巡逻 + 读插件对标库均已可用；跨次增量对比暂需口述配合（见第四节）。

## 一、何时启用

- 「扫一遍对标 / 对标最近怎么样 / 他们更新了没」
- 「看看我的号 / 我最近的数据」
- 「XX 这个号帮我盯着点」（单账号深巡）
- 用户发来一批账号链接 + 「都看看」

## 二、开工前：确认连接

先 `leadsradar_connection_status`，未连接按 onboarding 指引引导；每 8 秒复查，最多 12 次。

## 三、巡逻流程

### 第 1 步：确定巡逻名单

- 用户给了链接/名单 → 直接用
- 用户没给 → 先 `leadsradar_query_local_data(source="accounts")` 读插件对标库，有存量账号直接列出来让用户勾选（「插件里存着这 N 个对标：…，全巡还是挑几个？」）
- 对标库也是空 → **不要瞎猜**，回一句：「把要巡逻的账号主页链接发我（可一次多个），或者告诉我名字我去搜。」拿到名字用 `leadsradar_search_notes(名字/昵称)` 反查主页链接时，须向用户确认找到的账号对不对再继续。

### 第 2 步：逐个采集

每个账号调 `leadsradar_capture_profile(url, limit=30~50)`。

### 第 3 步：逐账号出要点（每账号三行以内）

1. **更新动态**：近期作品数、最新发布时间、更新频率（日更/周更/停更）
2. **爆款命中**：互动 ≥ 该账号近期均值 2 倍的作品——标题 + 数据 + 一句话「爆在哪」（选题踩点/标题钩子/形式变化）
3. **节奏变化**：发布频率或选题方向与近期相比有没有拐点

### 第 4 步：巡逻摘要（汇总输出）

```
【巡逻摘要 · N 个账号】

🟢 有爆款：@账号 ×《标题》（👍 2.3万，近期均值 2.8 倍）——爆在标题数字钩子
🟠 有更新：@账号 新增 3 篇 · @账号 新增 1 篇
⚪ 无动静：@账号、@账号

今天最该做的一件事：…（一句话，具体到动作）
```

呈现要求：**结论行放最前**（🟢🟠⚪ 分级即结论）、数字加粗、每账号要点不超过三行；账号 ≥3 个时在摘要前加一张「账号 × 新增/爆款/节奏」对比表，一屏看完。

「看我的号」走同一管线，视角换成自查：我的爆款是哪篇、我的节奏稳不稳、和对标比差在哪。

## 四、能力边界与降级

- **读对标库已可用**：`leadsradar_query_local_data(source="accounts")` 可列出插件里存的对标账号（含粉丝数/笔记数）
- **跨次增量对比仍需口述配合**：暂无「上次 vs 这次」自动对比。降级话术：「自动对比下次开。你把上次记得的情况告诉我（或直接看结果），我帮你人肉对比。」用户口述上次数据时，认真做对比再输出；也可用 `query_local_data(source="notes")` 按采集时间粗分两次巡逻的批次辅助对比
- **账号较多时**：profile 采集受限额（单批 300/30 分钟 600）约束——超过 5 个账号先告知预计耗时并确认；撞限额原样转述错误。

## 五、纪律

- 巡逻结论只报事实 + 可执行建议，不编造未采到的数据
- 对「我的号」的批评要直接但 constructive——用户要的是改进点，不是安慰
